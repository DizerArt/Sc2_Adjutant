# Compose — сборка и изоляция разработки

Git checkout на Windows: .gitattributes сохраняет LF для upstream Node LICENSE,
который проверяется byte-for-byte через compose-runtime.lock.json. Не форматировать
этот сторонний файл: исходные пробелы входят в закреплённую контрольную сумму.

Windows NSIS: [установка и проверка пакета](INSTALLATION.md). Текущий локальный
setup лежит в 02_application/release/compose-installer; это отдельная Compose
установка с собственным профилем, рядом с существующей Electron-версией.

Карта потерь: resources/map-bank включён в Tauri resources и stage; offline
scripts/verify-map-bank.cjs проверяет 35 PNG/40 map revisions, без скачиваний.
`smoke-compose.ps1 -PostmatchReplay "<абсолютный replay>" -RequireMapBackground`
проверяет настоящий native resolver/PNG HTTP. `-MinimapOnly` в отдельном test profile
принудительно проверяет извлечение миникарты. Оба режима требуют явного replay.
`node scripts/review-map-background.cjs "<полный owned smoke profile>"` поднимает
отдельный loopback стенд: terrain из smoke cache, игроки/позиции синтетические.
Обычные tests/startup не читают пользовательские карты и не запускают эти probes.

Проверка настоящего parser внутри native EXE на явно выбранном файле:
`powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/smoke-compose.ps1 -Executable "<полный путь EXE>" -PostmatchReplay "<полный путь .SC2Replay>"`.
Параметр opt-in; без него никакие личные реплеи не читаются. Временный профиль,
network/SC2/watch off, проверка SHA исходника, два запуска, счётчики вместо payload.
Tauri resource paths на Windows могут иметь `\\?\`; Node entrypoint нормализуется
на границе ReplayRunner. При воспроизведении запуска учитывайте этот формат пути.

Явная read-only диагностика выбранного реплея (не выполняется startup/tests):
`cargo run --manifest-path src-tauri/Cargo.toml --example check_postmatch --no-default-features --locked -- "<полный путь node.exe>" "<полный путь worker.mjs>" "<полный путь replay.SC2Replay>"`.
Она проверяет SHA, worker, native projection и Runtime/SQLite/publicfacts на
временном профиле без мониторинга/сети. Вывод — счётчики, не полный payload.
Ручной анализ имеет приоритет над автоматическим: sync/watcher не вправе менять
явно выбранный файл. Новая игра/clearStats по-прежнему отменяют подготовку/показ.

### Четыре виджета меню

Командные/FFA: используйте «Выбрать реплей…» в том же разделе. Файл открывается
в системном диалоге и только читается; это независимый просмотр, он не добавляет
одного фиктивного соперника в историю1×1. Отмена сохраняет предыдущий анализ.
Автоматическая привязка по истории пока только1×1. Режимы с минимум2командами,
современным Faster tracker и длительностью >2мин; co-op/arcade не гарантированы.

«Настройки → OBS → умный оверлей → Меню»: выберите сохранённый матч с реплеем и
«Подготовить анализ». Включите виды, нажмите «Разложить2×2» или перемещайте рамки
и тяните нижний правый угол. Стрелки двигают на ячейку, Shift+стрелки меняют размер;
поля под сеткой задают точные значения.32столбца×64строки относятся к полотну OBS.
Перекрытия разрешены; для перекрытого виджета используйте выбор/числовые поля.
Нажмите «Применить в OBS». Прежний `/widgets/` показывает включённые виды в меню.
Без связанного реплея анализ недоступен; неоднозначная автопривязка требует ручного
выбора. `review:browser` использует только синтетический матч, отдельно от production.

Если обычный preview EXE занят, staging допускает отдельную папку без остановки
текущего приложения: `node scripts/stage-compose.cjs --output compose-menu-postmatch-preview`.
Smoke этого пути: `powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/smoke-compose.ps1 -Executable "D:/dev/Sc2_Adjutant/02_application/release/compose-menu-postmatch-preview/SC2 Adjutant Compose.exe"`.

Цель: Windows 10/11 x64, Tauri 2 / Rust / React. Это экспериментальная миграция,
не завершённая замена Electron. Полный статус: [STATUS](STATUS.md).

## Инструменты на Windows

- Rust 1.99.1 через rustup, Cargo, rustfmt и Clippy; версия закреплена в корневом
  rust-toolchain.toml. Используется обычная пользовательская установка Windows.
- Microsoft C++ Build Tools, MSVC x64 и Windows SDK.
- Node.js и npm. На проверенной машине Node26.1.0/npm11.14.1; существующая
  установка не заменяется ради других проектов. Зависимости фиксирует package-lock.
- WebView2 для запуска Tauri (проверяется реальным native smoke).
- FFmpeg/FFprobe для дальнейшего объединения с медиадвижком.
- Docker Desktop/Compose — только вспомогательные сервисы и тесты, когда они нужны.

`scripts/compose.cjs` предпочитает установленный в профиле пользователя Cargo.
Локальный `.compose-tools` используется только как fallback, если системного Cargo
нет. Этот каталог, кэши и build outputs в исходники не входят. Старую локальную
копию инструментов можно убрать отдельно после завершения активных сборок.

## База данных и Docker

Решение пользователя25.10.2026: SQLite остаётся внутри приложения; Docker не нужен
пользователю для запуска. Вспомогательную PostgreSQL/Redis без реальной потребности
не добавляем. Для них можно будет создать отдельный Compose-профиль, отключённый
по умолчанию. Контейнеры и глобальные службы не запускаются из startup/tests.
Windows GUI/WebView2/установщик проверяются на Windows, а не в Linux-контейнере.

## Команды из 02_application

Для проверки изменений используйте [визуальный прогон](VISUAL-REVIEW.md):
`npm run review:browser` открывает управляемый браузерный стенд на тестовых
данных, `npm run review:compose` собирает и запускает настоящее приложение
с отдельным отмеченным профилем без сети и доступа к личной папке реплеев.
Первый проверяет внешний вид и состояния; второй — настоящие IPC/SQLite,
системные окна, выбор файлов и повторный запуск. Проверки SC2/OBS идут отдельно.

```powershell
npm ci
npm run dev:compose
npm run build:compose
npm run stage:compose
npm run smoke:compose
npm run smoke:compat
npm run typecheck
npm test
npm run test:compose
npm run clippy:compose
npm run fmt:compose
```

`build:compose` создаёт приложение и NSIS setup. `stage:compose` собирает отдельную
папку `release/compose-preview` с EXE и ресурсами. Это preview с установленным
WebView2, не заявленный полностью автономный portable-выпуск. Временный Node
runtime для существующего парсера/предметной логики включён явно; это не полное
нативное Rust-ядро. Модели озвучки не скачиваются сборкой.

Исходные команды `dev`, `build`, `pack:win`, `dist:win` по-прежнему относятся к
Electron. Его release workflow не переключён на экспериментальную миграцию.

## Проверка данных

Compose по умолчанию использует отдельный профиль Tauri, а не старый каталог
Electron. Для проверки существующих данных сначала вручную скопируйте каталог
данных через настройки старого приложения. Затем задайте абсолютный путь **копии**:

```powershell
$env:SC2_ASSISTANT_DATA_DIR = 'C:\AdjutantComposeTest\data'
```

При первом запуске CSV/XML/JSON импортируются в `compose.sqlite3`; исходные
файлы не перезаписываются, их байтовые копии сохраняются в каталоге backup.
Последующие изменения идут в SQLite и не синхронизируются обратно в Electron.
Нельзя одновременно направлять обе версии в один тестовый каталог.

Smoke сам создаёт синтетический профиль под `.compose-test-data`, отключает
SC2 autostart и внешние источники, проверяет настоящий WebView2/IPC/SQLite и
контрольные суммы оригиналов. Пользовательские SC2/OBS и исходные данные не нужны.

## HTML-оверлей OBS

В Tauri откройте «Настройки → Оверлей OBS», включите карточку и скопируйте адрес.
Добавьте в OBS источник «Браузер», вставьте URL и задайте размер, указанный рядом
с ним (по умолчанию1920×1080). Обычный адрес: `http://127.0.0.1:8766/widgets/`.
Выбираются положение карточки и размер полотна; настройки сохраняются в SQLite
независимо от прежнего окна «На экране игрока». Electron сообщает, что источник
доступен в Tauri, и не выдаёт фиктивный URL.

Без активного ranked1v1 с однозначно определённым соперником скрыта карточка.
Четыре кадра умного оверлея работают независимо от неё. Устаревшая карточка
скрывается; после восстановления связи страница продолжает получать состояние.
Локальная HTTP-граница отдаёт только HTML/ресурсы, зарегистрированные изображения
и ограниченный снимок оформления/карточки; заметки, BattleTag, пути,
история матчей и команды управления через неё недоступны.

Закрытие главного окна оставляет приложение в трее; «Открыть SC2 Adjutant»
возвращает окно, «Выход» завершает движок и его HTTP-сервер. Обычное сворачивание
сохраняет поведение панели задач. Закрытие приложения через «Выход» выключает URL.
При занятом порте приложение показывает ошибку и не останавливает чужой процесс.
Для другого порта задайте `SC2_COMPOSE_OVERLAY_PORT` (1024..65535) до запуска.
Порт0 разрешён только изолированному smoke. Старый проект использует8765.

`dev:compose` заранее собирает отдельные ресурсы `dist-obs`; правки страницы OBS
требуют `npm run build:obs` и обновления Browser Source, правки Rust — перезапуска
Tauri. Сборка не подключается к OBS и не изменяет его сцены. Полный каталог
виджетов, раскладки по режимам и четыре постматчевых вида пока не перенесены.

## Четыре кадра умного оверлея

В том же разделе ниже карточки доступны «Меню», «Загрузка», «Игра», «Пауза».
Включите умный оверлей в черновике, выберите кадр и включите/выключите его,
выберите своё изображение или верните стандартный вид. Выбор файла открывает
обычный диалог Windows. Отмена ничего не меняет; успешный импорт включает
выбранный кадр в черновике. «Применить в OBS» отдельно активирует весь черновик.
Предпросмотр и переключение вкладок не переключают рабочий источник.
Настройки черновика, применённая версия и копии изображений переживают перезапуск.

Стандартное меню прозрачно: для оформления нужна своя картинка. Из старого проекта
перенесены только поставляемые ресурсы: загрузочный GIF BRAT_OK и его постер,
контур Terran, затемнение паузы с подписью. Снимки экрана и локальные наборы из
data не копировались. Контур рассчитан на исходный HUD2560×1440, без автоматической
калибровки по расе или масштабу интерфейса. Своя картинка вписывается целиком;
у загрузки всегда непрозрачный фон, включая ожидание/ошибку изображения.

PNG/JPEG ограничены16МиБ, GIF128МиБ; максимум4096px на сторону и16млн пикселей.
GIF: до1800кадров/60секунд/600млн суммарных декодированных пикселей; копия
нормализуется в бесконечный цикл, первый кадр сохраняется для reduced-motion.
APNG не принимается. Проверяется реальное содержимое, а не расширение.
В профиле максимум128изображений/512МиБ; версии сохраняются, автоматического
удаления старых файлов нет. Оригиналы читаются без записи. Изображения находятся
под overlay-media рядом с compose.sqlite3; для переноса нужен весь профиль.

Применение использует номер версии: устаревший черновик не перезаписывает более
новые изменения. Общая команда настроек не может менять защищённые настройки
умного оверлея. HTTP остаётся только для чтения; имена файлов в снимок OBS не входят.

Отдельный принадлежащий runtime опрос /game и /ui не ждёт enrichment соперника.
Это дополнительный ограниченный читатель SC2, а не новый внешний сервис.
ScreenLoading выбирает загрузку, известные меню/ScreenScore — меню, пустые
activeScreens с игроками — игру/реплей. Пауза определяется по четырём свежим
неизменным положительным отсчётам таймера за3секунды; неподвижный таймер при
сетевом разрыве паузой не считается. Неизвестное состояние прозрачно, но уже
показанная загрузочная подложка удерживается при потере связи до известного
следующего состояния, выключения загрузки или всего оформления. Это не гарантия
сокрытия первого кадра загрузки; после обновления браузера старое состояние теряется.
Профили, калибровка и ручная аварийная cover исходного приложения ещё не перенесены.
